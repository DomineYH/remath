# ReMath PRD

Oct 27, 2026 · @Lee YongHan

ReMath는 예비교사가 가상 학생의 오개념을 발문으로 해결하는 연습을 하는 웹 앱이다. 이 문서는 클라이언트 데모(단일 HTML 목업, 8차 반복)에서 확정한 UI/UX를 React + Node.js + Supabase로 구현하기 위한 요구사항을 정의한다. 개발은 UI/UX를 먼저 완성하고 기능을 단계적으로 붙이는 순서로 진행하며, 실서버 배포 때마다 DB를 새로 생성하고 SQLite 백업을 함께 만든다.

## 1. 제품 개요

ReMath는 가상 학생(챗봇)의 오개념을 예비교사가 **설명 대신 발문으로** 해결하게 하고, 그 발문을 분류해 피드백하는 연습 도구다. 멘토 역할도 같은 챗봇이 맡아 정해진 트리거에서만 짧게 개입한다. 설계 근거는 PReMTA 프로젝트의 Master Template(Spine) + Overlay 구조와 Safety/Quality 가이드라인이다.

| 사용자 | 하는 일 | 진입 |
| --- | --- | --- |
| 관리자 | 시나리오 작성·검수·게시, 사용자·그룹 관리, 대화 기록 CSV 내보내기, AI 키·모델 설정 | `/admin` 로그인 (아이디 + 비밀번호) |
| 예비교사 | 소속 그룹에 할당된 시나리오를 골라 학생 챗봇과 대화, 세션 종료 시 발문 분석 확인 | `/` 로그인 (닉네임 + 비밀번호) |

**핵심 가치**

- 학생 챗봇은 질문받은 것만 답하고 스스로 진도를 나가지 않는다. 같은 오개념에 개념적 발문이 2회 들어와야 교정된다.
- 예비교사의 매 발화는 레버리지(Eliciting / Extending / Taking Over / Other)와 대상 영역으로 분류되고, 세션 종료 시 레버리지만 요약된다. 도달점·오개념 목록·진전 규칙은 절대 노출하지 않는다.
- 개인정보를 받지 않는다. 계정은 닉네임과 비밀번호뿐이다.

**범위**

| 포함 | 제외 (v1) |
| --- | --- |
| 데모에 있는 모든 화면과 흐름, 실제 LLM 호출, Supabase 영속화, 배포 시 DB 생성 절차, SQLite 백업 | 음성·이미지 입력, 학생 그림 렌더링, 다중 관리자 권한 등급, SSO, 모바일 네이티브 앱 |

## 2. UI/UX 설계 이력

클라이언트 데모는 단일 HTML 목업으로 2026-10-27 하루에 8차 반복을 거쳤다. 각 회차에서 확정된 결정이 아래 화면 명세의 근거이므로, 구현 시 다시 논의하지 않고 그대로 따른다.

| 회차 | 요청 | 확정된 결정 |
| --- | --- | --- |
| v1 | 템플릿 문서를 바탕으로 관리자 시나리오 생성 + 사용자 챗봇 대화 데모 | 관리자/예비교사 2역할 구조. 시나리오 위자드(학생 프로필 → 문제·초기 풀이 → 오개념·진전 규칙 → 멘토 트리거 → 검수 → 프롬프트 미리보기). 오개념마다 교정 키워드 + 1회차 망설임 대사 + 2회차 교정 대사. 데모용 내부 상태 패널(레버리지 누적·오개념 진행·마지막 트리거). 시나리오 5개(가브리엘·노아·지우 + 신규 하준·서연) |
| v2 | 이모지 드롭다운, 분류 기준 직접 작성 | 위자드에 5단계 “분류 기준” 추가: 분류명 · 해당하는 경우 · 예시 발문. 레버리지 분류가 하나도 없으면 \[CLASSIFICATION\] 블록과 세션 종료 분석을 모두 생략 |
| v3 | 성별·인종 이모지 금지, 챗봇 대화 언어 한/영, PReMTA 디자인 적용 | 학생은 동물, 멘토는 사물 이모지만. 시나리오마다 대화 언어 설정과 언어별 대사 세트(내부 설정은 공유). 프롬프트에 G) 대화 언어 섹션. 디자인: Fraunces/Geist 글꼴, 따뜻한 종이색 바탕, 인디고 강조색, 16px 둥근 카드 |
| v4 | 화면 언어 토글 | 헤더의 한│EN 토글이 앱 자체 문구를 바꾼다. 화면 언어와 챗봇 언어는 독립 설정 |
| v5 | 사용자 관리, 그룹별 접근 제어, 대화 CSV | 관리자 탭 4개(시나리오·사용자·그룹·대화 기록). 그룹에 할당된 시나리오만 구성원에게 노출, 미할당 그룹은 이용 불가. 사용자별·시나리오별·필터별 CSV(1행 = 1발화). 모든 대화 자동 기록 |
| v6 | AI API 키·모델·effort 설정 | 탭 5 “AI 설정”. 키 접두어로 공급자 자동 인식(sk-ant- / AQ.·AIza / sk-). 학생·멘토·분석 3개 챗봇이 각자 또는 공유 키를 쓰고, 공급자별 모델 목록과 모델별 effort 값만 표시 |
| v7 | 로그인 화면 | 닉네임 + 비밀번호만. 개인정보 수집 없음. 비밀번호 영문·숫자 혼합, 특수문자 허용(길이는 PRD에서 8자 이상으로 확정). 관리자는 `/admin` 주소로 별도 로그인 |
| v8 | 데모 환경에서 주소창 입력 불가 | 로그인 화면 하단에 “관리자 로그인 →” 링크 추가. 실서버에서는 `/admin` 경로가 정식 진입점 |

**반복에서 얻은 원칙**

- 내부 설정(도달점, 오개념, 진전 규칙)과 사용자에게 보이는 것을 화면에서부터 분리한다. 데모의 “내부 상태 패널”은 실서비스에서 관리자 대화 테스트에만 남긴다.
- 설정이 없으면 기능도 없다: 분류 기준이 없으면 분석을 하지 않고, 그룹 할당이 없으면 시나리오가 보이지 않는다. 기본값으로 채워 넣지 않는다.
- 두 개의 언어 축(화면 / 챗봇)과 두 개의 진입점(예비교사 / 관리자)은 서로 섞이지 않는다.

## 3. 화면 명세

데모 목업이 화면의 기준이다. 디자인 토큰(색·글꼴·반경·간격)은 목업의 `:root` 블록을 그대로 옥기고, 라이트·다크 모드와 모바일 폭(400px)을 모두 지원한다. 화면 언어의 기본값은 영어(EN)이고, 토글로 한국어로 바꾼다.

| 화면 | 경로 | 구성 요소 | 동작 |
| --- | --- | --- | --- |
| 로그인 / 계정 만들기 | `/` | 닉네임, 비밀번호, 탭(로그인│계정 만들기), 비밀번호 규칙 3개 실시간 표시, 개인정보 미수집 안내 | 계정 만들기 후 바로 로그인. 이메일·전화번호 형태 닉네임 거부 |
| 관리자 로그인 | `/admin` | 아이디, 비밀번호, “← 예비교사 로그인으로” | 실패 시 아이디/비밀번호 구분 없는 오류 메시지 |
| 시나리오 목록 | `/admin/scenarios` | 5단계 워크플로 카드, 시나리오 카드(이모지·이름·학년·문제·상태·언어·분류 수·이용 그룹), 버튼: 편집·프롬프트 보기·대화 CSV·대화 테스트 | 이용 그룹이 없으면 “할당된 그룹 없음 · 아무도 이용 불가” 경고 |
| 시나리오 위자드 | `/admin/scenarios/:id` | 왼쪽 단계 내비게이션 7개, 오른쪽 패널, 상단 챗봇 대화 언어 세그먼트(한국어│English), “예시로 채우기”, 하단 이전·초안 저장·다음·게시 | 언어 전환 시 언어별 필드만 교체, 내부 설정은 유지. 두 언어 세트 모두 보관 |
| 사용자 | `/admin/users` | 표(닉네임·그룹·이용 가능 시나리오·대화 수·가입일·비밀번호 변경일), 버튼: CSV·비밀번호·삭제, “사용자 추가” 모달 | 삭제 확인창에 대화 기록 수와 “CSV 먼저 내려받기” |
| 그룹 | `/admin/groups` | 그룹 카드(구성원 필, 할당 시나리오 필), 편집 모달(이름·구성원 체크·시나리오 체크) | 할당 시나리오 없음 = “이용 불가” 표시 |
| 대화 기록 | `/admin/logs` | 필터(사용자·시나리오), 표(시작·닉네임·시나리오·언어·발화 수·도달 여부), 보기 모달(전체 대화 + 분류 태그), “CSV 내려받기 (n건)” | 최신순 정렬 |
| AI 설정 | `/admin/ai` | 상단 3타일 요약, 챗봇 카드 3개(키 출처 선택 → 키 입력·인식 → 모델 → effort 버튼) | 키 입력 즉시 공급자 표시, 등록 후 입력란 비움, 마스킹 표시만 |
| 학생 선택 | `/practice` | 인디고 배너(인사), 접근 가능 시나리오 카드(언어·분석 여부·그룹 태그), “내 기록” 링크 | 그룹 없음 / 할당 없음 안내 문구 구분 |
| 대화 | `/practice/:scenarioId` | 헤더(학생 이모지·이름·\[CLASSIFICATION\] 토글·세션 종료·다른 학생), 문제 박스, 대화 로그, 빠른 질문 칩, 입력란 | 종료 시 멘토 요약 + 분석 리포트(분류 기준 있을 때만). 우측 내부 상태 패널은 관리자 테스트에서만 표시 |
| 내 기록 | /practice/history | 내 세션 목록(시작·시나리오·발화 수·도달 여부), 보기(전체 대화 + 세션 종료 분석 리포트) | 본인 세션만. 리포트는 세션 종료 때 보여 준 것과 같은 내용이며 도달점·오개념 목록은 담지 않음 |

**시나리오 위자드 7단계**

1. 학생 프로필: 학생·멘토 이모지(동물·사물 프리셋), 이름, 학년/주제, 한 줄 소개, 특성, 첫 인사말
2. 문제와 초기 풀이: 수학 문제, 초기 풀이, 그림/표현 묘사
3. 추론 프로필 · 오개념 · 진전 규칙: 오개념마다 교정 키워드, 1회차 망설임 대사, 2회차 교정 대사; 내부 도달점; “아하!” 대사
4. 멘토 트리거: Taking Over 코칭, 도움 요청 시 질문 프레임 2\~3개, 도달점 칭찬; 혼란 대사
5. 분류 기준: 레버리지·대상 영역 각각 분류명 · 해당 경우 · 예시 발문; 기본 세트 불러오기
6. 안전 · 품질 검수: 자동 점검 6개(PASS/FAIL/INFO) + 관리자 확인 4개. 모두 통과해야 게시
7. 프롬프트 미리보기 · 게시: Spine에 오버레이를 주입한 시스템 프롬프트 전문

## 4. 기능 요구사항

우선순위 P0는 v1 출시에 반드시 포함, P1은 출시 직후 반복, P2는 여유가 있을 때다. 데모에 있던 기능은 모두 P0이다.

| ID | 영역 | 요구사항 | 우선순위 |
| --- | --- | --- | --- |
| AUTH-1 | 인증 | 닉네임(2\~16자, 한글·영문·숫자·\_ . -)과 비밀번호만으로 계정 생성. 이메일·전화번호 형태 닉네임 거부 | P0 |
| AUTH-2 | 인증 | 비밀번호 8자 이상, 영문과 숫자 모두 포함, 특수문자 허용, 공백 불가. 입력 중 규칙 충족 여부 표시 | P0 |
| AUTH-3 | 인증 | `/admin` 경로의 관리자 로그인. 관리자 세션과 예비교사 세션은 분리 | P0 |
| AUTH-4 | 인증 | 본인 비밀번호 변경(현재 비밀번호 확인), 로그아웃 | P0 |

## 6. 데이터 모델 (Supabase / PostgreSQL)

모든 테이블은 `id uuid PK`, `created_at`, `updated_at`을 가진다. 시나리오의 언어별 대사 세트와 분류 기준은 구조가 자주 바뀜 수 있어 JSONB로 두고, 조회·집계가 필요한 대화 발화는 행으로 풀어 저장한다.

| 테이블 | 주요 컬럼 | 비고 |
| --- | --- | --- |
| `users` | `nickname text unique`, `password_hash text`, `role text` (teacher/admin), `pw_updated_at` | 개인정보 컬럼 없음. 해시는 argon2id |
| `groups` | `name text` |  |
| `group_members` | `group_id`, `user_id` | 복합 PK |
| `scenarios` | `slug`, `status` (draft/published), `lang` (ko/en), `student_prefix`, `mentor_prefix`, `grade`, `internal jsonb` (초기 풀이·그림·추론 프로필·절대 이해 못함·도달점·진전 규칙·오개념 설명), `classification jsonb` (leverage\[\], object\[\]), `compiled_prompt text` | `internal`과 `compiled_prompt`는 서버 전용, 예비교사 API에 절대 미반환 |
| `scenario_translations` | `scenario_id`, `lang`, `name`, `desc`, `problem`, `chars`, `greet`, `aha`, `t1`, `t2`, `t3`, `confused jsonb`, `elicit jsonb`, `misconceptions jsonb` (kw/h/c) | (scenario\_id, lang) unique |
| `group_scenarios` | `group_id`, `scenario_id` | 접근 제어의 유일한 근거 |
| `sessions` | `user_id`, `scenario_id`, `lang`, `started_at`, `ended_at`, `goal_reached bool`, `summary text`, `counts jsonb` | 관리자 테스트는 `user_id` = 관리자 |
| `turns` | `session_id`, `seq int`, `speaker` (teacher/student/mentor), `text`, `leverage`, `object`, `trigger` | CSV의 1행 |
| `ai_settings` | `role` (student/mentor/analysis) PK, `key_source` (own/student/mentor/analysis), `provider`, `key_ciphertext`, `key_masked`, `model`, `effort`, `key_added_at` | `key_ciphertext`는 서버만 복호 |
| `audit_log` | `actor_id`, `action`, `target`, `meta jsonb` | 사용자 삭제, 키 변경, 게시 등 |

**접근 규칙(RLS)**

- 예비교사는 `scenarios`에서 `status = published` 이고 본인 그룹에 할당된 행만, 그것도 `internal`·`compiled_prompt`를 제외한 뷰(`scenarios_public`)로만 읽는다.
- `sessions`·`turns`는 본인 것만 읽고 쓴다. 관리자는 전체.
- `ai_settings`·`audit_log`는 서비스 키로 접근하는 Node 서버만 읽고 쓴다. 클라이언트 직접 접근 금지.

## 7. 배포 시 DB 생성·백업 절차

&#91;embedded content: 배포 시 DB 생성 흐름 · 6단계, 1개 판정\]

실사용 서버에 올릴 때마다 `deploy.sh`가 이 순서를 강제한다. 검증에 실패하면 새 DB를 버리고 이전 DB가 그대로 서비스된다. 사람이 손으로 DB를 만들거나 스키마를 고치는 경로는 두지 않는다.

**deploy.sh 단계**

1. **새 DB 생성**: 새 서버에 배포할 때 Supabase Management API로 새 프로젝트를 만든다. 같은 서버에 재배포할 때는 기존 프로젝트에 새 마이그레이션만 적용한다. 어느 경우든 이전 프로젝트의 데이터는 읽지도 옮기지도 않는다.
2. **마이그레이션**: `db/migrations/*.sql`을 번호 순으로 적용. 테이블, RLS 정책, `scenarios_public` 뷰, 인덱스가 모두 여기 있다.
3. **시드**: 관리자 계정 1개(비밀번호는 배포 시 환경변수 `ADMIN_INITIAL_PASSWORD`로 주입, 해시만 저장), 기본 분류 세트(en/ko), 이모지 프리셋. 샘플 시나리오 5개는 `--with-samples` 옵션일 때만. 데모 계정은 어떤 옵션에도 넣지 않는다.
4. **스모크 검증**: service role로 연결, anon 키로 `scenarios.internal` 읽기가 거부되는지, 시드 행 수가 기대값과 같은지 확인.
5. **전환**: 통과 시에만 서버의 `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`를 교체하고 재시작. 이전 프로젝트는 관리자가 직접 삭제할 때까지 그대로 둔다. 자동 삭제는 없다.
6. **백업**: 전환 직후 `backup/remath-<YYYYMMDD>.sqlite`를 만든다.

**SQLite 백업 규칙**

- 운영 DB의 모든 테이블을 같은 컬럼으로 옵긴다(JSONB는 TEXT). `ai_settings.key_ciphertext`는 제외한다. 백업 파일에 키가 남지 않게 하기 위해서다.
- 배포 직후 1회, 이후 서버 스케줄러가 매일 1회 갱신. 보관 개수와 시각은 환경변수(`BACKUP_KEEP`, `BACKUP_AT`)로 정한다.
- 관리자 화면에서 최근 백업 시각과 파일 크기를 보여 준다(P1).
- 복구 스크립트 `restore.sh <file>`은 위 1−5단계를 같이 타면서 3단계의 시드 대신 백업 데이터를 넣는다.

## 8. AI 연동

대화 한 턴은 서버가 세 챗봇을 순서대로 호출해 만든다. 세 챗봇은 각각 다른 공급자·모델·effort를 쓸 수 있지만, 서버는 하나의 어댑터 인터페이스(`complete({system, messages, model, effort})`)만 본다.

| 챗봇 | 입력 | 출력 | 기본 effort |
| --- | --- | --- | --- |
| 학생 | 시나리오 시스템 프롬프트 + 대화 이력 + 예비교사 발화 | 학생 대사 한 개(짧게, 한 가지 생각만) | 낮음 |
| 분석 | 분류 기준(5단계) + 예비교사 발화 + 직전 학생 대사 | \[CLASSIFICATION\] JSON(leverage, object), 세션 종료 시 요약과 리포트 | 높음 |
| 멘토 | 트리거 종류 + 시나리오의 트리거 텍스트 + 최근 대화 | 멘토 코칭 1\~3문장. 트리거가 없으면 호출하지 않음 | 중간 |

**한 턴의 순서**

1. 분석 챗봇이 예비교사 발화를 분류한다(분류 기준이 없는 시나리오는 건너뜐).
2. 학생 챗봇이 답한다. 서버는 현재 오개념 교정 카운터와 도달 여부를 프롬프트에 주입해 진전 규칙을 지키게 한다.
3. 트리거 판정: leverage = Taking Over, 도움 요청, 도달점 도달 중 하나면 멘토 챗봇 호출.
4. 모든 발화를 `turns`에 기록하고 클라이언트에 스트리밍으로 내려보낸다.

**공급자 어댑터**

| 공급자 | 인식 접두어 | effort 파라미터 | v1 모델 목록 (2026-10 기준) |
| --- | --- | --- | --- |
| OpenAI | `sk-` (단, `sk-ant-` 제외) | `reasoning.effort` (none\~max) | gpt-6-astra, gpt-6.1-sol, gpt-6-sol, gpt-6-luna, gpt-5.6-terra, gpt-5.6-luna, gpt-5.5 |
| Anthropic | `sk-ant-` | `output_config.effort` (low\~max) | claude-fable-5-1, claude-opus-5-5, claude-sonnet-5-5, claude-haiku-5-5 |
| Google Gemini | `AQ.`(인증 키) / `AIza` | `thinking_level` (minimal\~high) | gemini-4-argon, gemini-3.8-pro, gemini-3.8-flash, gemini-3.6-flash, gemini-3.5-flash-lite |

- 모델 목록과 모델별 effort 허용값은 서버의 `providers.json`에 두고 배포 없이 갱신한다. 목록에 없는 모델 ID는 직접 입력을 허용한다.
- 키 등록 시 공급자에 최소 호출로 유효성을 확인하고(P1), 실패 사유를 관리자에게 보여 준다.
- 공급자 응답에 \[CLASSIFICATION\] 블록이 없거나 JSON이 깨지면 서버가 1회 재요청하고, 그래도 실패하면 해당 발화를 `Other`로 기록하고 계속 진행한다.
- 데모 목업의 규칙 기반 응답 엔진은 `MOCK_LLM=1`일 때 어댑터로 그대로 쓴다. UI 우선 개발 단계와 E2E 테스트에서 키 없이 동작하기 위해서다.

* Master Template은 영어판(기본)과 한국어판을 두고, 시나리오의 대화 언어에 맞는 판에 오버레이를 주입한다. 두 판은 섹션 구조와 플레이스홀더가 같아야 하며, 한 쪽만 고치면 검수에서 실패한다.

수집하는 개인정보는 없다. 계정은 닉네임과 비밀번호 해시뿐이고, 이메일·전화번호·실명을 받는 필드는 화면에도 DB에도 없다.

| 항목 | 규칙 |
| --- | --- |
| 닉네임 | 2\~16자, 한글·영문·숫자·`_ . -`. `@`가 들어가거나 숫자 7자리 이상 연속이면 거부. 중복 불가(대소문자 무시) |
| 비밀번호 | 8자 이상, 영문과 숫자 필수, 특수문자 허용, 공백 불가. argon2id로 해시. 로그인 실패 5회부터 닉네임 단위로 1분 지연 |
| 세션 | httpOnly · Secure · SameSite=Lax 쿠키. 예비교사 7일, 관리자 12시간. 관리자 세션은 `/admin` 경로에서만 발급 |
| 관리자 계정 | 1개로 고정. 배포 시드로 생성, 비밀번호는 환경변수로 주입. 화면에서 추가·삭제 불가. 비밀번호 초기화는 아래 절차로만 |
| API 키 | 서버의 `KEY_VAULT_SECRET`으로 AES-256-GCM 암호화해 `ai_settings.key_ciphertext`에 저장. 응답에는 공급자·마스킹 키(접두어 + 끝 4자)·등록일만. 로그와 SQLite 백업에 키를 남기지 않음 |
| 시나리오 내부 설정 | `internal`, `compiled_prompt`는 예비교사 API 응답에서 제외. 분석 리포트도 레버리지 분류만 담고 도달점·오개념 목록은 담지 않음 |
| 대화 기록 | 사용자 삭제 시 함께 삭제. CSV는 관리자 세션에서만 생성, 서버에 파일로 남기지 않음 |
| 아동 안전 | 시나리오 검수 항목과 시스템 프롬프트에 Safety/Quality 가이드라인 포함. 실제 인물 정보 생성 금지, 아동 대상 유해 요청 거부 |

**관리자 비밀번호 초기화 절차**

관리자 계정은 하나뿐이므로 화면에는 “비밀번호 찾기”가 없다. 초기화는 서버에 접속할 수 있는 운영자만 한다.

1. 서버에 SSH로 접속해 `npm run admin:reset-password`를 실행한다. 화면이나 API로는 초기화할 수 없다.
2. 새 비밀번호를 터미널 프롬프트에 두 번 입력한다. 명령 인수나 환경변수로는 받지 않는다(쉘 기록에 남지 않게).
3. 규칙(8자 이상, 영문·숫자)을 검사한 뒤 argon2id 해시로 `users`의 관리자 행을 갱신하고, 기존 관리자 세션을 모두 끝낸다.
4. `audit_log`에 `admin.password_reset`(시각, 서버 호스트명)을 남긴다. 비밀번호 자체는 어디에도 기록하지 않는다.

## 10. 개발 로드맵

&#91;embedded content: 개발 로드맵 · 4단계, 게이트 4개\]

1단계가 끝나면 목데이터로 돌아가는 앱이 데모 목업과 같은 모습으로 서 있고, 2·3단계는 그 화면 뒤에 실제 데이터와 모델을 끼운다. 화면은 1단계 이후 바뀌지 않는 것이 원칙이다.

| 단계 | 산출물 | 완료 기준(게이트) | 기간 추정 |
| --- | --- | --- | --- |
| 0 · 설계 확정 | 디자인 토큰 파일, 컴포넌트 목록, 화면 명세(3절) 동결, API·DB 스키마 초안, 프롬프트 스파인 | G1: 발주자가 디자인·화면 명세에 서명 | 1주 |
| 1 · UI/UX 구현 | React 전 화면(로그인, 관리자 5탭, 위자드 7단계, 대화), 목데이터 서비스, MOCK\_LLM 규칙 엔진, 한/EN, 라이트/다크, 모바일 | G2: 클라이언트가 목데이터로 전 화면 시연을 승인 | 3주 |
| 2 · 백엔드·DB | Node API, 인증, 그룹 접근 제어, Supabase 마이그레이션·시드·RLS, deploy.sh, SQLite 백업, CSV | G3: 스테이징에서 deploy.sh로 새 DB 생성 → 백업 → 복구까지 통과 | 2주 |
| 3 · LLM 연동·출시 | 공급자 어댑터 3종, 키 금고, AI 설정 저장, 검수·부하·보안 점검, 실서버 배포 | G4: 첫 그룹이 실서버에서 세션을 끝내고 CSV를 내려받음 | 2주 |

기간은 개발자 1명 기준 추정이며 발주자와 협의해 조정한다. 표의 날짜는 G1 통과일을 기준으로 채운다.

## 11. 비기능 요구사항과 미결 사항

| 항목 | 기준 |
| --- | --- |
| 응답 시간 | 화면 전환 1초 이내. 챗봇 응답은 스트리밍으로 첫 글자까지 3초 이내를 목표로 하고, 더 걸리면 타이핑 표시 |
| 동시 사용 | 한 반(30명)이 같은 시간에 대화해도 응답 순서가 섞이지 않음. 세션당 한 번에 한 턴만 처리 |
| 브라우저 | 최신 Chrome·Edge·Safari, 모바일 Safari·Chrome. 400px 폭에서 가로 스크롤 없음 |
| 접근성 | 키보드만으로 전 화면 조작, 포커스 표시, 폼 컨트롤에 레이블, 다크 모드 대비 유지 |
| 관측 | 서버 요청 로그에 발화 내용과 키를 남기지 않음. LLM 호출 실패율·지연을 공급자별로 집계 |
| 테스트 | 규칙 엔진·CSV·접근 제어는 단위 테스트. 로그인 → 대화 → 종료 → CSV, 위자드 작성 → 게시 → 그룹 할당 → 예비교사 조회는 E2E(Playwright, MOCK\_LLM) |
| 비용 | 학생 챗봇은 경량 모델·낮은 effort를 기본값으로 두고, 세션당 최대 턴 수(기본 40)를 두어 비용 상한을 걸어 둔다 |

**확정 사항 (2026-10-27 발주자 답변)**

| 항목 | 결정 |
| --- | --- |
| DB 새로 생성 단위 | 새 서버에 배포할 때 새 Supabase 프로젝트. 같은 서버 재배포는 마이그레이션만 |
| 이전 DB | 관리자가 삭제할 때까지 보관. 자동 삭제 없음 |
| 비밀번호 | 8자 이상, 영문·숫자 조합, 특수문자 허용 |
| 관리자 계정 | 1개 고정. 비밀번호 초기화는 서버 CLI 절차(9절) |
| 언어 | 영어가 기본값. 화면·챗봇·Master Template 모두 영어판이 기본이고 한국어판을 함께 제공 |
| 지난 세션 | 예비교사가 자신의 지난 세션 분석과 대화를 다시 열람(`/practice/history`) |
| 데모 요소 | 데모 계정 안내·초기화 버튼·예시 계정은 개발 시작부터 두지 않음. 테스트 빌드에도 없음 |
